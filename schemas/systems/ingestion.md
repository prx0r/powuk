# pow-frontier ingestion

## Watch list rather than firehose

Initial watched entities should be small and purposeful.

Examples:
- Normal Computing
- Extropic
- quantum hardware/software groups
- relevant semiconductor/memory projects
- major robotics/actuator/sensor advances
- decentralized compute/useful-work networks

## Research ingestion

Do not store paper = breakthrough.

Store:
- paper exists
- claim text
- experimental scale
- measured metric
- baseline
- caveats
- replication/production status where known

## Repository ingestion

Watch:
- releases
- tags
- selected main-branch commits
- protocol/benchmark changes

Do not treat commit count as innovation by itself.

## Hypothesis generation

A frontier event becomes a Seesaw candidate only when:
- mechanism is explicit
- constrained resource identified
- downstream measurable predictions exist

Otherwise remain `frontier_event`.
